# Мониторинг книг Григория Паламы — бесплатно через GitHub Actions

Проверяет Авито по расписанию **каждые 10 минут** (GitHub может задерживать задания), отправляет новые объявления в Telegram, помечает «Триады» как приоритетные. Телефон и компьютер могут быть выключены. Проверка выполняется в облаке GitHub, VPS не нужен.

> Важно: Авито может ограничивать автоматические запросы, а верстка страниц может меняться. Код не обходит CAPTCHA и другие ограничения. Живой доступ к Авито не тестировался. Это не гарантия обнаружения всех объявлений.

## 1. Создайте Telegram-бота

1. Откройте https://t.me/BotFather, отправьте `/newbot`, придумайте имя и username бота.
2. Скопируйте **токен** (не публикуйте его).
3. Откройте своего бота, нажмите **Start** и отправьте `/start`.
4. Чтобы получить chat ID, в адресной строке браузера откройте `https://api.telegram.org/botВАШ_ТОКЕН/getUpdates` (подставьте токен). В ответе найдите `"chat":{"id":123456789,...}` — число и есть chat ID. Если `result` пуст, напишите боту сообщение и обновите страницу. Не делитесь ссылкой с токеном.

## 2. Создайте репозиторий со смартфона

1. Зарегистрируйтесь на https://github.com.
2. Нажмите **+ → New repository**. Назовите `avito-palama-monitor`. Выберите **Public** (для стандартных GitHub-hosted runners в публичных репозиториях GitHub Actions бесплатны; содержимое репозитория и база найденных объявлений будут публичны). Если не хотите публичную историю, выберите **Private**, но тогда действуют лимиты минут GitHub Actions.
3. Добавьте из этого архива файлы `monitor.py`, `requirements.txt`, `.gitignore`, `README.md` через **Add file → Upload files**. Для workflow `.github/workflows/monitor.yml` проще включить в браузере **Desktop site**, затем **Add file → Create new file**, в поле имени ввести `.github/workflows/monitor.yml` и вставить его содержимое из архива. Сохраните (**Commit changes**).
4. В настройках репозитория откройте **Settings → Secrets and variables → Actions → New repository secret**. Создайте **два секрета**:
   - `TELEGRAM_BOT_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — число chat ID.
5. Откройте **Settings → Actions → General** и проверьте, что Actions разрешены, а в **Workflow permissions** выбран **Read and write permissions** (если настройка доступна). Это нужно для сохранения истории объявлений в репозитории.
6. Откройте вкладку **Actions → Проверка книг на Авито → Run workflow** для первого ручного запуска. При первом успешном запуске бот пришлёт сообщение об инициализации; уже существующие объявления запоминаются без отдельных уведомлений.

Дальше GitHub будет запускать проверки по расписанию. История сохраняется в `data/monitor.sqlite3` через коммиты от GitHub Actions. **Не удаляйте этот файл**, иначе бот снова посчитает следующий запуск первым.

## 3. Если что-то не работает

- **Actions → Проверка книг на Авито → последний запуск → scan** — здесь логи и ошибки.
- Нет сообщения от бота: проверьте оба секрета, нажмите `/start` у бота, посмотрите логи.
- `403`, CAPTCHA, «доступ ограничен», «неизвестная структура страницы»: сайт не дал прочитать выдачу; программа не обходит защиту. Можно параллельно использовать сохранённые поиски в приложении Авито.
- `git push` отклонён: проверьте права **Read and write permissions**, отсутствие правил защиты ветки, отсутствие параллельных изменений.
- В публичных репозиториях GitHub может отключать расписание после 60 дней без активности; проверьте вкладку Actions, если уведомления перестали приходить.

## Конфиденциальность и стоимость

Токен и chat ID хранятся в **GitHub Actions Secrets**, не добавляйте их в файлы или скриншоты. В публичном репозитории исходный код и SQLite-база (история найденных объявлений) доступны всем. Публичные репозитории с обычными GitHub-hosted runners обычно не расходуют платные минуты; правила GitHub могут измениться.

Возможны задержки cron-запусков и пропуски. Частые проверки могут противоречить ограничениям Авито; при блокировке лучше использовать официальные уведомления Авито.
